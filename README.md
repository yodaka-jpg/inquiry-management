## 使用技術

- Java 21
- Spring Boot
- Spring Security
- Spring Data JPA
- Thymeleaf
- MySQL 8.4
- Flyway
- Docker Compose
- Maven

### 前提条件

以下がインストールされている必要があります。

- Java 21
- Docker Desktop
- Git

### リポジトリの取得

```bash
git clone https://github.com/yodaka-jpg/inquiry-management.git
cd inquiry-management
```

### 環境変数の設定

`.env.example`をコピーして`.env`を作成します。

```bash
cp .env.example .env
```

`.env`はGitの管理対象外です。

### MySQLの起動

Docker Desktopを起動した状態で、以下を実行します。

```bash
docker compose up -d
```

MySQLの状態を確認します。

```bash
docker compose ps
```

`inquiry-mysql`が`healthy`になれば起動完了です。

### 環境変数の読み込み

```bash
set -a
source .env
set +a
```

### 自動テストの実行

```bash
./mvnw test
```

`BUILD SUCCESS`と表示されれば正常です。

### アプリケーションの起動

```bash
./mvnw spring-boot:run
```

`Started InquiryManagementApplication`と表示されたら、ブラウザで以下へアクセスします。

http://localhost:8080/

初回起動時にFlywayがテーブルと動作確認用データを自動作成します。

## 2. 動作確認手順
(どの画面でどう操作すると、何が起きるかを書く)

### ログイン

1. http://localhost:8080/ を開きます。
2. 動作確認用アカウントでログインします。
3. ログインユーザーの氏名と権限が表示されることを確認します。

### 問い合わせ詳細画面

ログイン後、以下へアクセスします。

http://localhost:8080/inquiries/1

以下が表示されます。

- 件名
- 依頼者
- 優先度
- 登録日時
- 問い合わせ本文
- 現在のステータス
- 現在の担当者
- 変更履歴

### ステータス変更

1. 「ステータス変更」で、表示されている変更先を選択します。
2. 必要に応じて200文字以内のコメントを入力します。
3. 「ステータスを変更」を押します。
4. 成功メッセージ、変更後のステータス、変更履歴を確認します。

許可される遷移は以下のとおりです。

| 変更前 | 変更後 |
|---|---|
| NEW | IN_PROGRESS |
| IN_PROGRESS | PENDING |
| IN_PROGRESS | DONE |
| PENDING | IN_PROGRESS |
| DONE | IN_PROGRESS |

`NEW → IN_PROGRESS`の際に担当者が未設定の場合、操作したユーザーが担当者として自動設定されます。

`DONE`へ変更すると`closed_at`へ現在日時が設定され、`DONE → IN_PROGRESS`では`closed_at`がクリアされます。

### 担当者変更

1. 「担当者割り当て」のプルダウンからユーザーを選択します。
2. 「担当者を変更」を押します。
3. 成功メッセージ、変更後の担当者、変更履歴を確認します。

担当者変更には以下のルールがあります。

- MEMBERは、未割り当ての問い合わせを自分に割り当てる操作だけ可能です。
- ADMINは、任意の有効ユーザーを担当者に設定できます。
- 担当者を未割り当てへ戻せるのは、ステータスがNEWの場合のADMINだけです。
- DONEの問い合わせでは担当者を変更できません。
- 無効ユーザーは担当者として選択できません。

### 排他制御

1. 同じ問い合わせ詳細画面を2つのタブで開きます。
2. タブAでステータスまたは担当者を変更します。
3. タブBを再読み込みせず、タブBでも変更を実行します。
4. 以下のメッセージが表示されることを確認します。

```text
他のユーザーが更新しました。画面を再読み込みしてください。
```

### 不正なステータス遷移

画面には、許可された変更先だけが表示されます。

ブラウザの開発者ツールなどで不正な値へ改変して送信した場合、サーバー側で拒否され、以下のメッセージが表示されます。

```text
このステータスへは変更できません。画面を再読み込みしてください。
```

### コメント文字数

コメントへ201文字以上入力すると、以下のメッセージが表示されます。

```text
コメントは 200 文字以内で入力してください。
```

この場合、問い合わせ本体の変更と履歴登録はロールバックされます。

### 存在しない問い合わせ

ログイン後、以下へアクセスします。

http://localhost:8080/inquiries/999999

以下のメッセージが表示されます。

```text
指定された問い合わせは存在しません。
```

### ログアウト

画面の「ログアウト」を押すとログイン画面へ戻ります。

## 終了手順

Spring Bootを実行しているターミナルで`Control + C`を押します。

MySQLを停止する場合は以下を実行します。

```bash
docker compose down
```

## 4. セルフチェック結果
(13 項目に○×を記入。×の理由も書く)
• ○ NEW の問い合わせで、変更先に「対応中」だけが表示される
• ○ NEW の問い合わせで「完了」に変更しようとしても弾かれる
• ○ DONE の問い合わせで「対応中」に戻せる
• ○ DONE → IN_PROGRESS のとき closed_at が NULL になる
• ○ NEW → IN_PROGRESS のとき、担当者未設定なら操作者が担当者になる
• ○ MEMBER で、他人が担当している問い合わせの担当者を変更しようとすると弾か
れる
• ○ MEMBER で、未割り当ての問い合わせを自分に割り当てられる
• ○ ADMIN で、担当者を未割り当てに戻せる(NEW のときのみ)
• ○ 無効ユーザーがプルダウンに出てこない
• ○ ステータス変更・担当者変更の両方で履歴が 1 件ずつ増える
• × コメントに 201 文字入れるとエラーメッセージが出る
• ○ メッセージ文言が仕様書と完全に一致している(句読点まで)
• ○履歴登録を意図的に失敗させると、本体の更新もロールバックされる
